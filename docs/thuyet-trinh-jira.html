Bug Report

Các trường bắt buộc khi log Bug

Environment

Browser, OS, Server, URL app.

Steps

Từng bước tái hiện theo đúng thứ tự.

Expected / Actual

Kỳ vọng thiết kế vs kết quả quan sát thật.

Priority

P1–P5 + giải thích 2–3 câu.

Attachment

Screenshot / video minh chứng.

Linked Issue

Bug relates to Story nghiệp vụ.

Ưu tiên

Thang Priority P1 → P5

PMứcVí dụ
P1BlockerSập toàn site / không dùng được hệ thống
P2CriticalLogin bằng email thất bại (case TrendStyle)
P3MajorSearch trả kết quả không liên quan
P4MinorCuộn ngang mobile Login
P5TrivialLệch 1px / lỗi thẩm mỹ rất nhỏ

Không mặc định mọi lỗi là Critical. Map Jira: Highest≈P1, High≈P2, Medium≈P3, Low≈P4, Lowest≈P5.

Vòng đời

Bug Lifecycle trên Kanban

To Do / Open→ In Progress→ Done / Resolved→ Closed hoặc Reopened
  • Dev: “The issue has been fixed. Please retest.”
  • QA OK: “Retested successfully. The issue is fixed.”
  • QA FAIL: “Retested. The issue still occurs.” → Reopened

  • Nhập email hợp lệ trong DB → báo sai tài khoản/mật khẩu.

Thực hành

Quy trình 5 bước trên Jira

  1. Tạo project Kanban NHOM11_SOFTWARE_TESTING.
  2. Tạo Story N11-1 (user story đăng nhập).
  3. Test web thật → Create Bug đủ trường + screenshot.
  4. Link Bug → Story; chọn Priority có giải thích.
  5. Chạy Lifecycle + Retest (ít nhất 1 lần Reopened).

Demo live: mở board N11, chỉ Issue, kéo status, đọc comment Retest.

Kết luận

Bài học & hướng mở rộng

  • Log Bug phải dựa trên Actual Result thật, không copy mẫu mù quáng.
  • Summary rõ + Priority đúng giúp Dev sửa nhanh hơn.
  • Lifecycle + Reopened chứng minh vòng kiểm soát chất lượng.
  • Mở rộng: dashboard theo Priority, tích hợp commit/PR, API tạo Bug từ test tự động.
